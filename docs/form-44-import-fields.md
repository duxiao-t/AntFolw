## 三、「检查项」字段的完整规则

### 3.1 表单里的配置

| 项 | 值 |
| --- | --- |
| 检查项 | `item-1`（检查项1，**必填**）、`item-2`（检查项2，**必填**） |
| 可选结果 | `pass`（通过）、`fail`（不通过）、`na`（不适用） |
| 结果 → 描述 | **`fail` 时必须写描述**（`descriptionRequiredByResult: {fail: true}`） |
| 照片上限 | 9 张（**导入不支持照片**，`images` 恒为空） |
| 允许描述 | 是 |

### 3.2 推荐写法：在「检查项」工作表里逐行填

一行 = 一个检查项。四个格子：行号、检查项、结果、描述。

| 行号 | 检查项 | 结果 | 描述 |
| --- | --- | --- | --- |
| 3 | 检查项1 | 通过 | |
| （留空） | 检查项2 | 通过 | |
| 4 | 检查项1 | 不通过 | 螺丝松动，已紧固 |
| （留空） | 检查项2 | 不适用 | |

可直接复制粘贴到「检查项」表第 3 行第 1 列（制表符分隔，「留空」处留真空）：

```
3	检查项1	通过	
	检查项2	通过	
4	检查项1	不通过	螺丝松动，已紧固
	检查项2	不适用	
```

填法要点：

| 项 | 规则 |
| --- | --- |
| 行号 | 「数据」表里这条记录的行号（从 3 开始，就是 Excel 左侧的行号）；**留空表示与上一行相同**；写错到不存在的行会当场报错 |
| 检查项 | `item-1` / `item-2` 或「检查项1」/「检查项2」都认；写别的会提示只能填哪两个 |
| 结果 | `pass`/`fail`/`na` 或「通过」/「不通过」/「不适用」都认；该列有下拉 |
| 描述 | 选「不通过」时必填；其他结果可留空 |
| 重复 | 同一张单里同一个检查项只能出现一行 |
| 空行 | 整行空着会被跳过，不影响其它行 |

### 3.3 兼容写法：在「数据」单元格里写一整段文本（旧模板，仍有效）

早期模板没有「检查项」工作表，整段内容写在一个单元格里，形如：

```
[{"id":"item-1","status":"pass"},{"id":"item-2","status":"pass"}]
```

每个键的允许值（兼容写法适用）：

| 键 | 含义 | 允许值 | 备注 |
| --- | --- | --- | --- |
| `id` | 检查项 id | **`item-1`** / **`item-2`** | **必须写 id**：漏写会报「缺少检查项编号（id）」；写成「检查项1」不会当场报错，但后面会因为对不上配置的编号而报「请完成检查项」 |
| `status` | 结果 | `pass` / `fail` / `na`，**也接受** `通过` / `不通过` / `不适用` | id 与中文都行（别名 `result` 亦可） |
| `description` | 描述 | 任意文本 | **`fail` 时必填**；别名 `remark` 亦可 |
| `images` | 照片 | — | 导入时被忽略，恒为空数组 |

兼容写法的两个限制：

- 一个单元格最多 500 字符，检查项多、描述长时容易超；
- 引号、括号必须成对，漏一个就整段读不出来。

### 3.4 同一行两处都写了怎么办

| 情况 | 结果 |
| --- | --- |
| 「数据」单元格有内容 | **以单元格为准**；「检查项」表里这一行的内容被忽略，预检提示区会说「第 N 行「检查项」已按单元格内容读取，明细表「检查项」里的对应内容被忽略」 |
| 「数据」单元格留空 | 用「检查项」表里行号对应的那几行 |
| 同一份文件里两种写法混用 | 允许，按行各自判断 |

**推荐用法**：新模板一律把「数据」表的「检查项」列留空，值只写在「检查项」表里，避免两份内容不一致。

### 3.5 校验逻辑（两种写法共用）

> 校验逻辑（`FormFieldValueValidator.validateChecklistValue`）：
> ① 每个 `required` 的检查项都必须有 `status`，否则 **`请完成检查项`**；
> ② `status` 命中 `descriptionRequiredByResult` 且无描述、无照片 → **`检查项描述必填`**。

明细表写法下，①②之前还会先做一层表内校验（检查项名是否在配置里、结果是否在配置里、同一检查项是否重复、`fail` 是否写了描述），报错会直接指出「明细表「检查项」第几行」。

## 五、常见易错点（按报错信息对照）

「适用」列说明该条属于哪种写法：**新** = 明细表写法，**旧** = 单元格文本写法，**通** = 两种都会遇到。

| 报错 / 现象 | 适用 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| `请完成检查项` | 通 | 两个检查项都必填，只填了一个、或整张明细表/整列为空 | **两个都要给结果**；不想评就填「不适用」 |
| `结果选了「不通过」时必须在「描述」里写明原因` | 新 | 选了不通过，「描述」列空着 | 补上原因 |
| `检查项描述必填` | 旧 | 文本里 `status` 是 `fail` 但没写 `description` | 补 `"description":"……"` |
| `「结果」只能填：通过、不通过、不适用；现在填的是「X」` | 新 | 结果用了配置外的词（如「合格」） | 只用「通过 / 不通过 / 不适用」或 `pass/fail/na` |
| `「结果」只能填 通过、不通过、不适用（现在填的是「X」）` | 旧 | 同上，但发生在文本写法里（文案略有差别） | 同上 |
| `「检查项」只能填：检查项1、检查项2；现在填的是「X」` | 新 | 检查项名称写错 | 写「检查项1 / 检查项2」或 `item-1 / item-2` |
| `缺少检查项编号（id），请按模板「填写说明」填写` | 旧 | 文本里漏了 `id` 键 | 用 `item-1` / `item-2` |
| `同一个检查项只能填一行，「检查项1」重复了` | 新 | 同一张单里同一个检查项写了两行 | 合并成一行 |
| `「行号」填的 9 在「数据」表里没有这条记录（本文件的数据行是 3-5）` | 新 | 行号写错，或「数据」表那一行是空行 | 按「数据」表左边的行号重填 |
| `请填写「行号」——也就是「数据」表里这条记录的行号（从 3 开始）` | 新 | 明细表第一行就留空，没有上一行可承接 | 第一行必须写行号 |
| `每个检查项都要写成 { ... }，现在有一个不是` | 旧 | 写成 `["通过","通过"]` 这种纯字符串列表 | 每项写成 `{...}`，或改用明细表 |
| `明细表「检查项」缺少第 2 行的字段标识，请重新下载模板填写` | 新 | 删掉了「检查项」表的第 2 行 | 重新下载模板 |
| `模板里声明的明细表「检查项」不存在，「检查项」将只按主表内容读取`（提示） | 新 | 「检查项」表被改名或删除 | 恢复表名或重新下载；否则紧接着会报 `请完成检查项` |
| `文件中的 N 行都已经导入过，没有新增数据` | 通 | 业务单号重复（`__import_key` 命中） | 换单号；或删掉「业务单号」列（改走文件内去重） |
| `模板里没有数据行` | 通 | 数据填到了第 1/2 行 | 数据从**第 3 行**开始 |
| `文件不是系统生成的导入模板（缺少 __antflow_meta）` | 通 | 删了 `__antflow_meta` 工作表（隐藏表） | 重新下载模板，只从第 3 行填数据 |
| `模板包含表单里不存在的字段「xxx」，请重新下载模板` | 通 | 手工加了模板没有的列 | 不要加列；主表按模板给的 3 列填，检查项写在「检查项」表里 |
| `只有已发布的表单可以导入数据` | 通 | 选了 DRAFT 表单（04:22 就是踩了这个） | 先在表单管理里**发布** |
| `只接受系统生成的 .xlsx 模板` | 通 | 传了 `.xls` / `.csv` | 只传 `.xlsx` |
| 表头文字改了 | 通 | — | **无影响**（列匹配只认第 2 行 fieldId）；可以改，但**别删列、别删第 2 行** |

## 六、怎么自己确认能过（不用等我）

1. 表单管理 → 发布页 → 下载该表单的导入模板（**表单配置变了就要重下**：模板与当前表单结构绑定，旧模板会被拒）
2. 导入数据 → 选「上传 Excel（可批量）」→ 选表单 44 → 上传 → **看第 3 步「预检结果」**
3. 预检是**不落库**的，可以反复试：
   - `可导入 N / 有错误 0` → 点下一步提交
   - `有错误 M > 0` → 逐行错误表会给出 **Excel 真实行号 + 字段名 + 原因**
4. 有错行时：
   - 勾「跳过错误行继续」→ 只导能过的行（部分成功）
   - 不勾 → 整批取消（**0 行落库**），改完文件重传

明细表引起的错误，错误表里的「行号」是**主表那条记录的行号**，而原因里会额外写「明细表「检查项」第 5 行：…」——两个行号对得上，就知道改哪一格。

## 七、这份表单本身的一个建议

表单 44 是当初为验证「发布检查」临时建的测试表单，两个检查项都被设成**必填**，
导致「检查项」无法留空 —— 对"只想导入几行文本"很不友好。

如果它只是练手用，两种更省事的选择：

1. **只填「单行文本」**：不行，检查项必填会挡住 → 必须给「不适用」占位
2. **新建一张更宽的表单**（把检查项设为非必填、或干脆不要这个字段），再导数据

如果要按业务场景（比如设备点检、巡检记录、客户回访）设计一张字段更完整的表单并配套示例，
说明场景即可 —— 那样一次的模板能长期复用。
