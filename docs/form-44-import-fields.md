## 三、「检查项」字段的完整规则

### 3.1 表单里的配置

| 项 | 值 |
| --- | --- |
| 检查项 | `item-1`（检查项1，**必填**）、`item-2`（检查项2，**必填**） |
| 可选结果 | `pass`（通过）、`fail`（不通过）、`na`（不适用） |
| 结果 → 描述 | **`fail` 时必须写描述**（`descriptionRequiredByResult: {fail: true}`） |
| 照片上限 | 9 张（**导入不支持照片**，`images` 恒为空） |
| 允许描述 | 是 |

### 3.2 单元格写法（JSON 数组）

```json
[{"id":"item-1","status":"pass"},{"id":"item-2","status":"pass"}]
```

### 3.3 每个键的允许值

| JSON 键 | 含义 | 允许值 | 备注 |
| --- | --- | --- | --- |
| `id` | 检查项 id | **`item-1`** / **`item-2`** | **必须写 id**，写「检查项1」会报 `检查项缺少 id` |
| `status` | 结果 | `pass` / `fail` / `na`，**也接受** `通过` / `不通过` / `不适用` | id 与中文都行（别名 `result` 亦可） |
| `description` | 描述 | 任意文本 | **`fail` 时必填**；别名 `remark` 亦可 |
| `images` | 照片 | — | 导入时被忽略，恒为空数组 |

> 校验逻辑（`FormFieldValueValidator.validateChecklistValue`）：
> ① 每个 `required` 的检查项都必须有 `status`，否则 **`请完成检查项`**；
> ② `status` 命中 `descriptionRequiredByResult` 且无描述、无照片 → **`检查项描述必填`**。

## 五、常见易错点（按报错信息对照）

| 报错 / 现象 | 原因 | 正确做法 |
| --- | --- | --- |
| `检查项缺少 id` | JSON 里写了 `"id":"检查项1"` 或漏了 `id` 键 | 用 `item-1` / `item-2` |
| `请完成检查项` | 两个检查项都 `required`，你只填了一个、或整列留空 | **两个都要给结果**；不想评就填 `na` |
| `检查项描述必填` | 选了 `fail` 却没写 `description` | 补 `"description":"……"` |
| `检查项结果「X」不在配置里` | `status` 用了别的词（如"合格"） | 只用 `pass`/`fail`/`na` 或 `通过`/`不通过`/`不适用` |
| `检查项的每一项都必须是 JSON 对象` | 写成 `["通过","通过"]` 这种纯字符串数组 | 每项必须是 `{...}` |
| `文件中的 N 行都已经导入过` | 业务单号重复（`__import_key` 命中） | 换单号；或删掉「业务单号」列（改走文件内去重） |
| `模板里没有数据行` | 数据填到了第 1/2 行 | 数据从**第 3 行**开始 |
| `这不是系统模板，请重新下载` | 删了 `__antflow_meta` sheet、或删了第 2 行 | 重新下载模板，只从第 3 行填数据 |
| `未知字段：xxx` | 手工加了模板没有的列 | 不要加列；按模板给的 3 列填 |
| `只有已发布的表单可以导入数据` | 选了 DRAFT 表单（你 04:22 就是踩了这个） | 先在表单管理里**发布** |
| `只接受系统生成的 .xlsx 模板` | 传了 `.xls` / `.csv` | 只传 `.xlsx` |
| 表头文字改了 | **无影响**（列匹配只认第 2 行 fieldId） | 可以改，但**别删列、别删第 2 行** |

## 七、这份表单本身的一个建议

表单 44 是当初为验证「发布检查」临时建的测试表单，两个检查项都被设成**必填**，
导致「检查项」列无法留空 —— 对"只想导入几行文本"很不友好。

如果它只是练手用，两种更省事的选择：

1. **只填「单行文本」**：不行，检查项必填会挡住 → 必须给 `na` 占位
2. **新建一张更宽的表单**（把检查项设为非必填、或干脆不要这个字段），再导数据

如果要我按业务场景（比如设备点检、巡检记录、客户回访）设计一张字段更完整的表单并配套示例，
告诉我场景就行 —— 那样一次的模板能长期复用。
