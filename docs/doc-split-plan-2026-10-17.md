# README.md 与 AGENTS.md 的职责划分方案

2026-10-17。分析对象：根 `README.md`（554 行）与 `AGENTS.md`（275 行）。

## 一、定位、读者与核心用途

| 维度 | `README.md` | `AGENTS.md` |
| --- | --- | --- |
| 定位 | 项目对外的**产品与使用说明书** | 仓库对内的**改代码协作契约** |
| 面向读者 | 初次接触的人：评估者、使用者、部署/运维者、外部贡献者 | 在这个仓库里动手的人：AI agent、本仓库开发者 |
| 核心用途 | 判断"这东西能不能用"→ 装起来 → 跑起来 → 配起来 → 出问题怎么办 | 判断"我该怎么改"→ 读什么 → 哪些不能动 → 怎么验证 → 怎么提交 |
| 典型问题 | 是什么？怎么装？怎么配？报错怎么办？有什么边界？ | 先读哪些文档？哪些是不变量？命令怎么跑？提交格式？ |
| 变更触发 | 产品能力、安装方式、配置项、对外边界变化 | 工程约定、目录职责、不变量、编码/提交规范变化 |
| 生命周期 | 长期稳定，面向未来使用者 | 随开发实践演进，面向"下一个人" |
| 是否对外承诺 | 是（发布、支持、边界都算承诺） | 否（内部纪律，可随团队调整） |

**一句话区分**：README 回答"**这是什么、怎么用**"；AGENT 回答"**怎么改、不能碰什么**"。

## 九、调整后的自检（三条不变量）

1. **零复述**：任取一条事实，正文只在 SSOT 文件出现一次；另一处最多一行指针。
2. **可独立阅读**：只读 README 能装、能跑、能配、能排障；只读 AGENT 能改代码、能验证、能提交，且不会因为缺信息而误判。
3. **无悬空指针**：所有跨文件引用在调整后都指向存在的章节号。
