# 项目上下文

## 项目目标

AntFlow 是面向企业的表单与审批平台，提供桌面管理端、移动审批端、流程运行时和第三方集成。

## 系统地图

| 区域 | 职责 | 事实来源 |
| --- | --- | --- |
| `backend` | Spring Boot API、审批引擎、RBAC、审计、迁移 | `backend/src/main` |
| `frontend` | Umi Max 桌面管理端 | `frontend/src`、`frontend/config` |
| `mobile` | Vite 移动审批端 | `mobile/src` |
| PostgreSQL | 业务数据、权限、任务及菜单版本 | `backend/src/main/resources/db/migration` |
| MinIO | 附件和审计归档 | `compose.yaml`、后端存储配置 |

## 关键流程

- 登录 → JWT 与数据库会话校验 → 请求主体快照 → 端点能力 → 资源授权 → 数据范围。
- 移动端登录、恢复和刷新统一优先采用 `mobileBootstrap.user`，保留 deptId 等完整组织信息；应用和测试共用 antd-mobile React 19 弹层渲染器。
- 表单发布 → 版本快照 → 流程发起 → 任务流转 → 历史与事务消息。
- 文本/表格导入 → 选项数据版本发布 → 表单绑定确定版本 → 按表单、实例或填报记录上下文查询。
- 服务端页面能力清单 + 数据库菜单结构 → 后端过滤导航 → 桌面注册表解析路由。
- 桌面设计器组件配置只走字段注册表的可选 `ConfigPanel`，共用 `node + updateProps(patch)` 接口；23 类字段有面板，description / scan_code / location 无组件专属配置。基础设置、校验、显示逻辑与联动由 Inspector 管理。

## 不变量与约束

- Flyway 仓库最新版本为 V67；历史迁移已冻结，后续迁移只前滚。仓库版本不代表生产已上线。
- 公司设置页提供真实列表与创建；通讯录按显式公司上下文管理部门和成员。公司创建保留 `system:company:manage`，部门公司创建后不可改，父子关系、移动及根排序必须同公司。
- 组织管理与业务管理的公司边界和原能力、数据范围相交；非全局管理员 ALL/CUSTOM 不能越过本人公司，无有效部门不回退公司 1。业务归属取实例/填报的行内快照；NULL/inferred 待人工确认，普通正文、附件和待办不提前放行。本人已确认历史及跨公司任务关系保留既有读取/审批例外，不扩大报表、导出与管理权；运行时选择器仍按配置候选。
- 成员通过 `deptId` 调岗；仅全局管理员可将本地账号跨公司调整。任意企微用户映射阻止跨公司调岗，同公司手工部门调整仍可能被同步覆盖。上级、下属及负责人跨公司关联须先处理，失败不自动清除；调岗不改历史公司快照。
- `t_form_resource_grant` 只定义已发布表单的使用范围（目录、打开、草稿、发起）。
- 表单使用对非全局管理员要求：运行时能力 + COMPANY 公司门槛 + USER/ROLE/DEPARTMENT 任一主体授权；仅全局管理员能修改公司门槛。V55 为存量表单补迁移时已有公司，新公司及新表单默认未获公司授权。
- 本人旧草稿的公司门槛按草稿快照校验，调岗不改归属；表单读取、预览、保存和提交验证草稿所有者及表单匹配，选项查询使用 dataId 上下文。撤销使用授权后保留本人草稿，禁止继续写入。
- `t_form_maintainer` 定义模板维护成员；非管理员还必须持有对应的表单/流程原子能力。
- 每张有效表单至少保留一名有效维护人；停用最后一名维护人由服务层和数据库双重拒绝。
- 表单数据与审批实例按各自能力和数据范围裁决，不依赖表单使用授权。
- 移动端 users/departments 选择器登录可见；桌面选择器使用 `/api/pickers/**`。两者的**列表**端点只回 id/姓名/部门/工号（不下发登录账号）；账号与工号只走按 id 的端点与 `/api/users`。
- 企业微信同步新建账号使用不可知随机凭据；绑定已有本地账号不得覆盖其密码。
- 企微同步按领取 UUID 与 120 秒租约认领，30 秒续租，批次事务内核验并锁定持有权；失租停写。恢复时完整重新拉取并幂等执行，只有完整拉取成功后才停用缺失人员，不保存外部数组偏移。
- 新流程必须 V2，实例先于任务加锁；任务还需核对运行状态、当前轮次/节点、类型与操作者。撤回修改保持 RUNNING + __rework__。旧 V1 写路径待生产运行/重提实例、关联待办与可恢复作业全部为零才退役。
- 流程通知统一落事务 outbox；失败消息按监控公司范围查询，只返回元数据与脱敏提示。单条重放要求独立能力 `workflow:outbox:retry`（默认 SELF）、实例管理范围及 DEAD 状态，UUID 与稳定投递键不变，保留至少一次投递。
- 附件存储、上传、关联与探测位于 `attachment`，草稿位于 `form.runtime`，运行时组织选择位于 `org`；移动 controller 保持 URL/JSON 适配。两端生产传输类型从同一后端 OpenAPI 快照生成，移动只引用 `shared/api.generated.d.ts`，不依赖 Umi。
- 26 类字段共用校验 fixture；约束按 rules→props→默认值。正式提交媒体时长以服务端 ffprobe 实测为准，V57 存可选 duration_seconds，旧文件受限再提交时补测；只读历史不重验，缺工具明确拒绝。V56 只补 checkbox 标签，不扩大 BI 脱敏白名单。
- 生产种子管理员必须通过 `ANTFLOW_BOOTSTRAP_ADMIN_PASSWORD` 一次性初始化；公开默认密码只允许在 `local` profile。
- 选项数据源发布版本不可变；表单快照固定版本，运行时查询必须复用表单、实例或填报记录的授权上下文。
- 选项数据源仅在从未发布且没有表单（含版本快照）引用时可以删除；已发布数据源仅可停用。
- `t_form_definition_version` 只增不删：BI 台账靠它解析历史字段标签，清理旧版本会静默改变历史报表列名。
- BI 只读视图（V45）直连库读取，绕过应用三层鉴权，**有意接受**；账号仅限全局可信场景，不提供给公司管理员。BI 账号只授视图，任何改为基表授权的改动都要重新评审。
- BI 人员字典不暴露登录工号，台账不暴露自由文本、附件或复杂字段原值。

## 外部依赖

- PostgreSQL 17：主数据与迁移。
- MinIO：附件与归档。
- OIDC、企业微信：外部身份和组织集成，按配置启用。
