# 表单数据导入说明（免 JSON 版）

面向要做**历史数据补录**的人：把已经发生过的单据批量补进系统，记录直接记为「已提交」，不进入审批流程、不产生待办、不通知任何人。

自「免 JSON」改造起，结构化字段（检查项 / 明细表 / 矩阵填空）不再要求在单元格里写一整段带括号的文本，而是**一个字段一张工作表、一行一条记录**，用「行号」把明细挂回主表。改造前下载的老模板照样能用（见第四节）。

---

## 一、两种导入方式

| 方式 | 从哪里进 | 适合什么 | 一次多少条 | 出错时的反馈 |
| --- | --- | --- | --- | --- |
| 在线填写 | 后台「提交数据」→「导入数据」→ 第 1 步选「在线填写一条」→ 选表单 → 在表单界面里填 → 提交导入 | 十来条以内、字段少、需要用界面上的下拉/日期/检查项控件、或者只有一条要补 | 1 条 / 次（可点「再填一条」连续录） | 提交时立即校验；不通过会列出是哪个字段、给「返回修改」 |
| 上传 Excel | 同一入口的第 1 步选「上传 Excel（可批量）」：选表单 → 下载模板 → 填好上传 | 几十条以上、数据本来就在别人的台账里、需要一次补一批 | 1–20000 行 / 个文件 | 上传即预检，逐行列出错误，可以反复试，不落库 |

两条路径共用同一套字段校验与落库逻辑，所以不会出现「Excel 能过、在线填不过」的差异。导入人就是提交人。

两者的关键差别只有一处：**在线填写没有「预检」这一步，点提交就直接写入**；上传 Excel 可以先预检、确认无误再导。所以不确定数据对不对时，先走 Excel 预检更稳。

> 在线填写同样可以填「业务单号」（界面上叫「外部单号」，可选）：填了按它防重，留空则不参与防重，单据编号由系统生成。

## 二、模板长什么样

一张模板由若干张工作表组成：

| 工作表 | 默认是否隐藏 | 作用 |
| --- | --- | --- |
| `数据` | 否 | 主表，一行一条记录 |
| 每个结构化字段各一张（名字就是字段名，如「检查项」） | 否 | 明细表，一行一条子记录，用「行号」指回主表 |
| `__antflow_meta` | 是 | 模板的身份信息：属于哪张表单、哪个版本、有哪些字段、哪几张是明细表 |
| `__dict` | 是 | 下拉候选值的来源 |
| `填写说明` | 否 | 每个字段一句话的填写要求 |

一个字段有没有明细表，只取决于它的类型：`checklist`（检查项）、`table_list`（明细表）、`matrix_fill`（矩阵填空）三种各有一张；其余字段仍然只是主表里的一列。

### 2.1 主表「数据」

```
第 1 行：  业务单号  |  单行文本  |  检查项（见「检查项」表）     ← 人看的列名，可以改
第 2 行：  __import_key | apt6UwBB | kil-AWrU                   ← 程序对齐用，隐藏，别删
第 3 行起：数据
```

- 第 2 行被设成「零高度」隐藏，但仍可编辑：选中第 1、2 行取消隐藏就能看到字段标识。
- 列的身份只认第 2 行。第 1 行的文字**可以改**（例如把「检查项（见「检查项」表）」改成「检查情况」），不影响导入。
- 结构化字段在主表只留一个**指针列**，列名后面带「（见「XX」表）」。这一列留空即可，值填在对应的明细表里。
- 数据必须从第 3 行开始。整行全空的行会被自动跳过，不算数据行。
- 「业务单号」是模板自带的保留列，不是表单字段：填了就按它判重（同一张表单内唯一），不填则只能按内容在本文件内去重。

### 2.2 明细表

三类明细表的结构统一：**第 1 行列名（给人看）／第 2 行字段标识（隐藏，给程序对齐）／第 3 行起数据**。

#### 检查项（checklist）

| 行号 | 检查项 | 结果 | 描述 |
| --- | --- | --- | --- |
| 3 | 检查项1 | 通过 | |
|  | 检查项2 | 通过 | |
| 4 | 检查项1 | 不通过 | 螺丝松动，已紧固 |
|  | 检查项2 | 不适用 | |

- 一行 = 一个检查项。「结果」列有下拉（通过 / 不通过 / 不适用），也可以直接打字，中文名和英文编号都认。
- 「描述」列：只有配置了「某结果必须写描述」时才必填（表单 44 是「不通过」必须写）。
- 同一个检查项在同一张单里只能出现一行，重复会报错。

#### 明细表（table_list）

假设明细里有「名称」（文本）和「数量」（数字）两个子字段：

| 行号 | 名称 | 数量 |
| --- | --- | --- |
| 3 | 合同 | 2.5 |
| 3 | 补充协议 | 1 |
| 4 | 会议纪要 | 3 |

- 列 = 明细里的子字段，一列一个；列的顺序与表单配置一致。
- 一行 = 一条明细。同一张单有几条明细就写几行，行号相同。
- 附件类子字段和纯说明类子字段不出列；如果手工补一列并填了内容，会报「是附件类字段，Excel 无法携带文件」（表格带不了文件）。

#### 矩阵填空（matrix_fill）

假设矩阵的行是「第一行 / 第二行」，列是「上午 / 下午」：

| 行号 | 行 | 上午 | 下午 |
| --- | --- | --- | --- |
| 3 | 第一行 | 1.5 | 2 |
| 3 | 第二行 |  | 7 |
| 4 | 第二行 | 3 | 4 |

- 「行」列填矩阵的行名，一行 = 矩阵的一行，不必把每一行都写满；行数不多时该列带下拉。
- 后面每一列对应矩阵的一列，留空就是这一格不填。
- 单元格是数字型时只能填数字（不要写「两个」）；文本型照常填。
- 矩阵的同一行在同一张单里只能出现一次。

#### 关于明细表的三条通用规则

1. 第 1 行的列名只是给人看的，程序按第 2 行对齐；改列名没事，删第 2 行会出事。
2. 明细表里可以留空行（整行空），会被直接跳过。
3. 不要自己加列、不要改第 2 行的标识。加了没有对应标识的列，内容会被忽略。

### 2.3 「行号」列怎么填

| 问题 | 答案 |
| --- | --- |
| 填什么 | 这条明细属于「数据」表里的第几行——**就是 Excel 左边显示的行号**，从 3 开始 |
| 为什么需要 | 一个字段的所有明细都堆在一张表里，只能靠行号判断哪几条属于同一张单 |
| 连续几条属于同一张单 | 只在第一条写行号，后面**留空**（留空自动承接上一行） |
| 能写 3.0 吗 | 能，表格把数字显示成 3.0 也认 |
| 写了不存在的行 | 直接拒绝，并告知本文件的数据行有哪几行 |
| 第一行就留空 | 报错：请填写「行号」 |

```
行号  检查项     结果     描述
3     检查项1    通过
      检查项2    通过
4     检查项1    不通过   螺丝松动，已紧固
      检查项2    不适用
```

> 行号指向的是「数据」表里**实际有内容**的行。如果「数据」表第 4 行整行空着、数据写在第 5 行，那明细里就要写 5，不能写 4。

### 2.4 `__antflow_meta` 删了会怎样

这张表只有一行文本，记录模板属于哪张表单、表单版本、字段清单，以及哪几张工作表是明细表。

| 操作 | 结果 |
| --- | --- |
| 删除整张表 | 报「文件不是系统生成的导入模板（缺少 __antflow_meta）」，整份文件被拒 |
| 清空内容 | 报「模板元数据为空，请重新下载模板」 |
| 改成别的表单的元数据 | 报「模板属于另一张表单，请重新下载」 |
| 表单配置改过但还在用旧模板 | 报「表单结构已更新，请重新下载模板后再导入」 |

结论：不要动它，也不要试图手写。表单配置一变就重新下载模板。

## 三、三种结构化字段：旧写法 vs 新写法

下面的「旧写法」仍然可用（见第四节），但推荐用新写法：不用记括号和引号，明细多长都不怕，写错了报错也更具体。

### 3.1 检查项（checklist）

| | 旧写法（单元格文本，兼容） | 新写法（明细表，推荐） |
| --- | --- | --- |
| 填在哪 | 「数据」表的「检查项」列 | 「检查项」工作表，第 3 行起 |
| 一条记录占几行 | 1 个单元格装下全部检查项 | 每个检查项一行 |
| 写法 | 一整段带方括号、花括号的文本 | 四个格子：行号 / 检查项 / 结果 / 描述 |
| 容易错在 | 漏引号、漏花括号、把「检查项1」当编号 | 行号漏填、结果写了配置里没有的词 |

**不要这样写**（在「数据」表的「检查项」单元格里）：

```
[{"id":"item-1","status":"pass"},{"id":"item-2","status":"pass"}]
```

**这样写**（在「检查项」工作表里）：

| 行号 | 检查项 | 结果 | 描述 |
| --- | --- | --- | --- |
| 3 | 检查项1 | 通过 | |
|  | 检查项2 | 通过 | |

### 3.2 明细表（table_list）

| | 旧写法（单元格文本，兼容） | 新写法（明细表，推荐） |
| --- | --- | --- |
| 填在哪 | 「数据」表的明细字段列 | 该字段对应的工作表，第 3 行起 |
| 一条明细占几行 | 挤在同一个单元格里 | 一行一条 |
| 写法 | 一整段带方括号的文本，每条明细用花括号括起来 | 每个子字段一列，逐行填 |
| 条数多时 | 容易撞上「单元格不超过 500 字符」 | 没有 500 字符限制，受 20000 行限制 |

**不要这样写**（一个单元格里塞完）：

```
[{"c1":"合同","c2":"2.5"},{"c1":"补充协议","c2":"1"}]
```

**这样写**：

| 行号 | 名称 | 数量 |
| --- | --- | --- |
| 3 | 合同 | 2.5 |
| 3 | 补充协议 | 1 |

### 3.3 矩阵填空（matrix_fill）

| | 旧写法（单元格文本，兼容） | 新写法（明细表，推荐） |
| --- | --- | --- |
| 填在哪 | 「数据」表的矩阵字段列 | 该字段对应的工作表，第 3 行起 |
| 写法 | 一整段文本，按「行编号 → 列编号 → 值」三层嵌套 | 「行」列写行名，后面每列写一个值 |
| 容易错在 | 行列编号写错、值写成字符串数字 | 行名写了配置里没有的词 |

**不要这样写**：

```
{"cells":{"r1":{"c1":"1.5","c2":"2"}}}
```

**这样写**：

| 行号 | 行 | 上午 | 下午 |
| --- | --- | --- | --- |
| 3 | 第一行 | 1.5 | 2 |
| 3 | 第二行 |  | 7 |

## 四、老模板还能用吗

能。兼容性按下面四条执行：

1. **单元格里有内容，就以单元格为准。** 同一行既写了旧写法、又在明细表里写了内容时，明细表的那部分**被忽略**，预检的提示区会明确说一句：
   「第 N 行「检查项」已按单元格内容读取，明细表「检查项」里的对应内容被忽略」。
2. **单元格留空，才用明细表。** 这是新模板的默认填法。
3. **两种写法可以在同一份文件里混用**：第 3 行用旧写法，第 4 行用明细表，都能导进去。
4. **改造前下载的模板不需要重下**：模板里没有明细表清单，导入时会完全跳过明细表，只按主表读。但表单结构改过（加字段、改选项、改标签）之后，旧模板一律失效，必须重新下载。

> 版本号没有变化（仍是第 1 版），所以「老模板继续可用」与「表单改了要重下」两条同时成立。

## 五、常见错误对照表

报错文案都是实际会出现的原文，可在预检结果、失败明细或页面提示里对照。

### 5.1 明细表自身的问题

这一类里，「行号」写错、缺第 2 行、文件读不出来属于**整张表读不下去**：预检会直接失败并弹出这条提示，不会进到逐行错误表。而单元格内容类的问题（结果、检查项、描述、矩阵行）是逐行的，会出现在逐行错误表里，可以只改那一行。

| 报错原文（节选） | 原因 | 怎么改 |
| --- | --- | --- |
| 「行号」填的 99 在「数据」表里没有这条记录（本文件的数据行是 3-5） | 行号指向了不存在的记录，或「数据」表那一行是空行 | 按「数据」表左边显示的行号重填；数据行范围报错里已经给出 |
| 「行号」必须是数字，现在填的是「第三行」 | 行号写成了文字 | 改成数字 |
| 请填写「行号」——也就是「数据」表里这条记录的行号（从 3 开始） | 明细表第一行的行号就空着，没有上一行可承接 | 第一行必须写行号 |
| 「结果」只能填：通过、不通过、不适用；现在填的是「差不多」 | 结果不在表单配置的选项里 | 从下拉里选，或改成配置里的名称/编号 |
| 「结果」不能为空，只能填：通过、不通过、不适用 | 填了检查项但没选结果 | 补上结果；不想评就选「不适用」 |
| 「检查项」只能填：检查项1、检查项2；现在填的是「外观」 | 检查项名称不在表单配置里 | 用表单里配置的检查项名称 |
| 「检查项」不能为空，请填写检查项名称或编号 | 只填了结果、检查项那格空着 | 每一行都要写是哪个检查项 |
| 同一个检查项只能填一行，「检查项1」重复了 | 同一张单里同一个检查项写了两行 | 合并成一行 |
| 结果选了「不通过」时必须在「描述」里写明原因 | 配置了「不通过必须写描述」，「描述」列空着 | 补上原因 |
| 「行」只能填：第一行、第二行；现在填的是「第三行」 | 矩阵行名不在配置里 | 用配置里的行名（下拉可选） |
| 矩阵的同一行只能填一行，「第一行」重复了 | 同一张单里同一矩阵行写了两行 | 合并成一行 |
| 数值单元格只能填数字，现在填的是「两个」 | 数字型矩阵格写了文字 | 改成数字 |
| 「XX」是附件类字段，Excel 无法携带文件，请改用表单填写 | 明细表里给附件类子字段填了内容 | 清空该列；附件只能在表单界面里传 |
| 明细表「检查项」缺少第 2 行的字段标识，请重新下载模板填写 | 删掉了明细表的第 2 行 | 重新下载模板 |

### 5.2 模板与表单对不上

| 报错原文（节选） | 原因 | 怎么改 |
| --- | --- | --- |
| 模板里声明的明细表「检查项」不存在，「检查项」将只按主表内容读取（**提示，不是报错**） | 明细表被改名或删掉了 | 恢复表名，或重新下载模板；否则该字段会因「没填」而在后面报必填错误 |
| 模板属于另一张表单，请重新下载 | 拿 A 表单的模板导进了 B 表单 | 选对表单后重新下载 |
| 表单结构已更新，请重新下载模板后再导入 | 表单加/删了字段、改了选项或标签 | 重新下载模板，把数据重贴一遍 |
| 模板版本不受支持，请重新下载 | 模板来自更早/更新的一代格式 | 重新下载 |
| 模板包含表单里不存在的字段「xxx」，请重新下载模板 | 手工加了模板里没有的列，或第 2 行被改过 | 不要加列；重新下载 |
| 第 3 列缺少字段标识，请重新下载模板 | 「数据」表第 2 行有空格子（该列的字段标识为空） | 重新下载，不要动第 2 行 |
| 字段「xx」在模板里出现了多次 | 同一列在第 2 行重复出现了同一个标识 | 重新下载 |
| 只接受系统生成的 .xlsx 模板 | 上传了 .xls / .csv，或文件名后缀被改过 | 用 Excel「另存为」.xlsx |
| 文件不是系统生成的导入模板（缺少 __antflow_meta） | 删了隐藏的元数据表 | 重新下载 |
| 只有已发布的表单可以导入数据 | 选的是草稿状态表单 | 先发布，再导入 |

### 5.3 数据与重复

| 报错原文（节选） | 原因 | 怎么改 |
| --- | --- | --- |
| 请完成检查项 | 有必填的检查项没给结果（整张明细表为空、或只填了部分检查项） | 每个必填检查项都要有结果；不想评就选「不适用」 |
| 文件中的 N 行都已经导入过，没有新增数据 | 业务单号全部命中已导入的记录 | 换单号；或清空「业务单号」列改走内容去重 |
| 业务单号不能超过 128 个字符 | 单号太长 | 缩短到 128 字符以内 |
| N 行因业务单号或内容重复被跳过（**提示**） | 部分行的单号已存在，或与文件前面的行内容完全相同 | 属正常现象；确认被跳过的行是否本该导入 |
| 文件没有「业务单号」列，重复数据只在本次文件内按内容去重，跨批次无法识别（**提示**） | 删掉了「业务单号」列 | 想跨批次防重就保留并填写该列 |
| 单行文本 exceeds maxLength | 单行文本超过 255 字符 | 截短到 255 字符以内 |
| 字段名 is required（例：必填字段「金额」为空时报「金额 is required」） | 该字段必填但整列为空 | 补上该字段的值 |

> 「重复」不算错误行，只算「将跳过」。预检里三个数字是分开的：可导入 / 有错误 / 将跳过。

## 六、校验与反馈机制

### 6.1 预检不落库，可以反复试

选「上传 Excel」后，向导共四步：选择表单 → 上传文件 → 预检结果 → 确认导入。文件一选中就自动预检，**预检只读不写**，改完文件重新上传即可，不会留下半条数据。

预检结果给三样东西：

| 内容 | 说明 |
| --- | --- |
| 三个数字 | 可导入 / 有错误 / 将跳过。三者相加等于文件里的数据行总数（按行计，不按错误条数计） |
| 列对账 | 每一列是否在表单里找到、类型、是否必填、是否匹配；文件里缺了表单的列、或出现了表单不支持的列时，这一步直接卡住，不能继续 |
| 逐行错误 + 原始值预览 | 每条错误带 Excel 真实行号、字段名、原因；预览显示前 20 行解析出来的原始值，方便确认没有串列 |

### 6.2 有错行时的两条路

| 选择 | 结果 |
| --- | --- |
| 不勾「跳过错误行继续」 | 一行不合格就整批取消，**0 行落库**，报错消息里列出前几条问题行 |
| 勾选「跳过错误行继续」 | 只导能过的行，坏行单独回报；页面显示「将导入 N 行，丢弃 M 行」 |

勾选框只在「有错误」时可勾；有错误又不勾时，无法开始导入。

### 6.3 失败明细怎么拿

- 页面上的失败明细表就是「行号 / 字段 / 原因」，可以滚动查看；
- 点「下载失败明细」导出 CSV，列头固定为 `行号,字段,原因编码,原因`，文件名带批次号，可直接用 Excel 打开（已处理中文编码）；
- 明细表引起的错误，CSV 里的「行号」是**主表那条记录的行号**，而「原因」里还会再写一句「明细表「检查项」第 5 行：…」，两个行号都能对上。
- 错误条数有上限：一次最多返回 2000 条，超出时页面会提示只显示了一部分。

### 6.4 在线填写的反馈

选「在线填写一条」后，界面分三步：选择表单 → 填写内容 → 提交结果。

| 结果 | 表现 | 能做什么 |
| --- | --- | --- |
| 成功 | 「导入完成」，显示成功 / 重复跳过 / 失败三个数字 | 点「再填一条」继续录同一张表单；或关闭 |
| 校验不通过 | 红色提示，下面列出「字段明细」（哪一项、什么原因），并给出错误码 | 点「返回修改」回到填写页改这一条，已填内容保留 |
| 业务单号重复 | 提示单号已导入过 | 换一个外部单号，或清空外部单号按新增提交 |

在线填写**不提供失败明细 CSV**（一次只有一条记录，页面上的字段明细就是全部信息）。

## 七、完整操作示例：表单 44「结构校验验证表单」

### 7.1 先看清这张表单

| 项 | 内容 |
| --- | --- |
| 字段 1 | 单行文本（`apt6UwBB`），非必填，最多 255 字符 |
| 字段 2 | 检查项（`kil-AWrU`）：检查项1、检查项2 都必填；结果三选一：通过 / 不通过 / 不适用；选「不通过」必须写描述 |
| 照片 | 不支持导入（Excel 带不了文件） |

因为两个检查项都必填，所以每条记录的检查项都要有结果——不想评就选「不适用」。

### 7.2 下载模板

「导入数据」向导第 1 步选表单 44 → 点「下载导入模板」。下载到的文件里应有这几张表：`数据`、`检查项`、`填写说明`，以及隐藏的 `__antflow_meta`、`__dict`。

主表三列：`业务单号`、`单行文本`、`检查项（见「检查项」表）`。

### 7.3 填「数据」表（第 3 行起）

| 业务单号 | 单行文本 | 检查项（见「检查项」表） |
| --- | --- | --- |
| EXT-2026-001 | 设备日常点检 | （留空） |
| EXT-2026-002 | 设备周检-发现异常 | （留空） |
| （留空） | 仅文本，检查项统一填不适用 | （留空） |

同样的内容，可直接复制粘贴到 Excel（制表符分隔，从第 3 行第 1 列开始贴）：

```
EXT-2026-001	设备日常点检	
EXT-2026-002	设备周检-发现异常	
	仅文本，检查项统一填不适用	
```

「检查项」这一列**留空**——值写在下面的「检查项」表里。如果两处都写，以单元格内容为准，明细表那部分会被忽略。

### 7.4 填「检查项」表（第 3 行起）

| 行号 | 检查项 | 结果 | 描述 |
| --- | --- | --- | --- |
| 3 | 检查项1 | 通过 | |
| （留空） | 检查项2 | 通过 | |
| 4 | 检查项1 | 不通过 | 螺丝松动，已紧固 |
| （留空） | 检查项2 | 不适用 | |
| 5 | 检查项1 | 不适用 | |
| （留空） | 检查项2 | 不适用 | |

可直接复制粘贴（制表符分隔，「（留空）」的地方留真空）：

```
3	检查项1	通过	
	检查项2	通过	
4	检查项1	不通过	螺丝松动，已紧固
	检查项2	不适用	
5	检查项1	不适用	
	检查项2	不适用	
```

要点：

- 第 2、4、6 条的行号留空，自动承接上一行，所以三张单分别落在 3、4、5 行；
- 第 4 行选了「不通过」，描述必须写，否则报「结果选了「不通过」时必须在「描述」里写明原因」；
- 第 5 行的两个检查项都选「不适用」，是为了满足「两个检查项都必填」；
- 检查项写「检查项1」或 `item-1` 都可以，结果写「通过」或 `pass` 也都可以。

### 7.5 上传、预检、导入

1. 向导第 2 步上传填好的文件，等自动预检；
2. 第 3 步应看到：**可导入 3 / 有错误 0 / 将跳过 0**；列对账里三列都是「匹配」；提示区没有警告；
3. 第 4 步点「开始导入」；
4. 结果显示：成功 3、重复跳过 0、失败 0；
5. 到「提交数据」列表里按业务单号搜 `EXT-2026-001` 核对。

如果第 3 步出现「有错误」，按第五节的表格对照改，改完重新上传——预检不落库，试多少次都不会产生脏数据。

### 7.6 这个例子里两个容易忽略的点

- 第 5 行的业务单号留空：这一行跨批次无法识别重复。同一份文件再导一次时，它只会在本文件内按内容去重，因此会**再新增一条**。想避免就给它一个单号。
- 明细表里行号的 3 / 4 / 5 是「数据」表里的行号，不是「检查项」表里的行号。后者只在报错时出现。

## 八、限制速查

| 项 | 限制 |
| --- | --- |
| 文件格式 | `.xlsx`（`.xls`、`.csv` 不接受） |
| 文件大小 | 10 MB |
| 在线填写 | 1 条 / 次 |
| 数据行 | 1–20000 行 |
| 列数 | 不超过 50 列（含「业务单号」；字段太多时下载模板就会提示无法导入） |
| 单元格长度 | 主表单元格不超过 500 字符；明细表单元格无此限制 |
| 表头长度 | 不超过 100 字符（超长的字段名在模板生成时自动截断） |
| 业务单号 | 不超过 128 字符 |
| 附件 / 照片 | Excel 导入不支持；必填的附件字段会让整张表单无法导出模板，这类表单无法用 Excel 补录 |
| 错误明细 | 一次最多返回 2000 条 |
