## 固定默认值与接口

公司仍只有现有的 id、name、createdAt，复用 GET/POST `/api/companies`，不增加地址、LOGO、删除或修改公司接口。
本片不增加数据库迁移或依赖。
POST 只接受 name：服务端 trim 后要求 1～128 字符，不使用请求中的 id/createdAt，保留现有管理能力和审计。
非全局管理员的公司列表只返回本人部门所属公司；无有效部门则返回空，不能默认为公司 1。

部门所属公司创建后保持只读。子部门的 companyId 必须等于父部门，部门移动/排序必须限于同公司；
已有跨公司父子关系先报告、人工确认，本批不自动重写组织或历史单据。
成员调岗继续使用已有 PUT `/api/users/{id}` 的 deptId，不新增迁移/调岗专用接口。
跨公司仅允许全局管理员操作本地账号；存在企微用户映射的成员禁止跨公司，
同公司部门调整允许但可能被后续同步覆盖。上级、下属及部门负责人关联须先处理，不自动清除。
公司创建保留 `system:company:manage` 的现有委派规则。

## 已完成的实施步骤

1. **公司页面落地。** 在已经注册的 `/settings/company` 用真实公司列表和创建弹窗替换演示保存。
   将未注册的公司创建实现迁到活入口，删除死页面；没有公司管理能力时只读，权限仍由后端裁决。
2. **通讯录选择公司。** 去掉 `companies[0].id ?? 1`。唯一公司可自动选，多公司必须明确选；
   换公司清空部门、成员勾选、搜索和分页，所有相关查询键携带公司上下文。未选公司不请求部门，也不能建部门/成员。
3. **组织边界收口。** 后端检查请求公司与当前非管理员公司、父子部门公司及移动目标公司。
   同公司的根部门排序不参与其他公司的序号；直接调用 API 不能绕过公司选择。全局管理员保留显式跨公司管理能力。
4. **成员部门编辑。** 编辑/创建弹窗提供授权部门树；保存发送 deptId，禁用的部门不能选择。
   调岗触发现有授权版本失效，直属上级/下属跨公司约束继续由后端验证；失败保留编辑内容，不自动删除关联关系。
5. **契约与验收。** 更新真实 OpenAPI 快照和生成物；后端真库、前端行为测试、移动回归、构建、导入边界和健康指标通过。
   在本机双公司栈验证创建、刷新、切换、调岗以及 API 拒绝；成功后更新 PROJECT/HANDOFF/DECISIONS 并提交。
