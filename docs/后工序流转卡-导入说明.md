# 后工序流转卡的导入：从「一维长表」到「一行一物料」

## 一、先说清你的数据是什么

你给的文件 **只有 1 个 sheet**（`一维表`），不是多个表：

| 项 | 实测 |
| --- | --- |
| 规模 | 4420 行 × 11 列 |
| 结构 | **一维长表**：前 8 列是物料属性，后 3 列是「字段名 → 内容」的工序键值对 |
| 数据形状 | **260 个物料 × 17 道工序**，每个物料恰好 17 条 |
| 17 道工序 | 刻字、纠偏、拆支架/盖子、敲水管、研磨、门线测漏、型腔试压、水道试压、打毛刺、磨面/精铣底面、清洗、擦门线、掏水道铝屑、上支架堵头、上油道堵头、上水道堵头、备注 |
| 属性一致性 | 260 个物料的 6 个属性**全部一致、0 处冲突** → 可无损透视 |

所以痛点是：**长表里「哪一列是工序」由 `字段名` 的值决定**，没法直接倒进字段固定的表单。

## 二、系统里现在长什么样

**表单**：`后工序流转卡`（id=46，已发布，version=2）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 物料代码 | 文本 | ✅ | 一个物料一行 |
| 产线 / 型号规格 / 客户 / 简称 / 所属系列 | 文本 | | 来自一维表的前 8 列 |
| 优先级 | 数字 | | |
| 第一位 | 文本 | | |
| **工序** | **明细表** | | 子字段：`工序名`（必填）+ `内容` |

**为什么工序用明细表而不是 17 个字段**：你选了「工序可增减」。写成固定 17 列，以后加工序就得改表单结构、还会让已发布的旧数据对不上列；存成明细表后，加工序只是多几行数据，表单不用动。

**代价**：列表页里「工序」显示成一条清单，不是 17 列并排。点开详情能看到全部工序。

**导入步骤**：

1. 表单管理 → 找到「后工序流转卡」（如果列表里没有，重启一次 backend 容器让缓存刷新）
2. 数据页 → 「导入数据」→ 选择这张表单
3. 上传 `后工序流转卡_导入模板_已填充.xlsx`
4. 看第 3 步预检：预期 **可导入 260 行 / 错误 0**
5. 提交 → 260 个物料入库，每条的「工序」下有 17 行

## 四、以后再来一批数据，怎么做

两条路，按频率选：

| 场景 | 做法 |
| --- | --- |
| 偶发一次 | 把新文件发我，我按同样规则转一次（几分钟） |
| 经常有 | 需要系统支持「宽表直接导入」：上传任意宽表 → 按列名匹配表单字段、未匹配的列折进明细表。这是新功能，要单独做 |

现在的手工路线：下载模板 → 把「数据」sheet 填成一行一物料 → 把工序填到「工序」sheet（行号写主表行号，连续同一物料可留空）→ 导入。

## 五、这份数据本身的两个注意点

1. **`内容` 列不是纯 0/1**：刻字有「加工中心前刻字 / 烤漆后刻字」，试压有「半成品试压 / 洗油-上水道堵头-试压」，备注是长文本。所以「内容」只能当文本存，不能当布尔。
2. **`第一位` 列在 260 个物料上全是 `0`**（实测），暂时没有区分度，先按原样保留；如果它其实有别的含义，告诉我它的业务规则再调整。

## 六、这次用的替代方案（供追溯）

表格插件在这台机器上把 `D:\` 盘符解析成了 `e:\D:\...`，读不了文件。我改用 POI 直接只读解析（没有改动你的原文件），生成模板时 `schemaHash` 用数据库里的 `schema::text` 计算，并与库内 `sha256` 的结果逐字节比对一致（`86c36dc6…`），所以导入不会报「模板与表单不匹配」。
